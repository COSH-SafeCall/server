# 커밋·PR 작성 예시

[문서 목록](README.md) · v4.2-web-mvp

아래는 현재 0~4장 리팩토링을 제출할 때 사용할 문안이다. 실제 커밋·PR·병합이 수행되었다는 기록은 아니다. 브랜치·base·PR 번호는 저장소의 실제 대상에 맞춰 결정한다.

## 커밋 제목

```text
refactor: 4장까지 SafeCall API를 최종 웹 명세에 맞춤
```

문서 정리만 제출하는 경우:

```text
docs: 서버 설정·검증·배포 문서를 웹 MVP 기준으로 정리
```

## PR 제목과 본문

제목: `웹 MVP 최종 명세에 맞춰 인증·사용자·통화 API 정비`

```markdown
## 변경 내용

기존 인증·사용자·홈·통화 구현을 v4.2-web-mvp의 공통 설계와 1~4장 계약에 맞췄습니다. 보안 쿠키·CSRF·웹 OAuth로 인증하고, 통화는 페이지 소유권과 생성 시 고정한 정책으로 관리합니다.

- 최종 DB DDL 및 JDBC 행 매핑·DTO 동기화
- 프로필·연락망 PATCH, 문서 단건 조회, 동의 철회 응답 최신화
- C07 재개, grant 세대·예산·lease·최대 통화 시간 반영
- 삭제와 상태 전환의 원자 처리, 트랜잭션 결과에 따른 키 수명 관리
- 환경변수 양식 및 설정·API 검증·배포 문서 정리

## 검증

실행한 명령과 실제 결과를 이곳에 기입합니다. docs/verification.md와 결과 JSON의 실행 시각을 확인한 뒤 사용하며, 이전 실행 수량을 새 검증 결과로 복사하지 않습니다.

## 적용 범위

DDL은 새 DB 설치용이며 기존 DB 이관은 별도입니다. 실제 카카오/Gemini·브라우저 검수, 운영 외부 키 저장소, 5~7장 신규 API와 ACCOUNT 외부 정리는 후속 범위입니다.
```

제출 전 [변경 리포트](web-v4-refactor-report.md)와 실제 diff의 범위를 맞춘다. 문서만 수정한 PR에는 코드 리팩토링 문안을 그대로 사용하지 않는다. 개인 환경 파일·키·build 결과를 포함하지 않는다.
