# 재검토 발견 사항 추가 수정 — 2026-09-14

이 문서는 이전 보완 기록이다. 이후 발견한 발급 제한 시간·키 생성 동시성 수정과 최신 스키마·검증 결과는 [전체 재검토 수정 보고서](backend-full-review-fixes.md)를 참고한다.

## R1: 최초 통화 설정과 일치할 때만 재개

최초 발급 시각과 통화별 HMAC을 callSession에 기록한다. HMAC에는 모델·API 버전·음성·전체 조립 지침이 반영된다. 프롬프트 원문·새 개인화 스냅샷은 DB에 저장하지 않는다.

재개 시 유효한 동의와 현재 회원 정보를 확인하고, 최초 발급 시각을 기준으로 같은 지침을 재구성한다. HMAC이 일치할 때만 토큰을 발급하여 기존 회원의 호칭·나이·성별·안전 지침을 유지한다. 생일/자정이 지나도 나이 계산 기준은 바뀌지 않는다. 프로필·release·코드 변경으로 같은 설정을 재구성할 수 없거나 기존 통화에 HMAC이 없으면 RESUMPTION_FAILED로 종료하며 새로운 정책의 토큰을 발급하지 않는다. 이 경우 기존 한 번의 재개 예산은 복구하지 않는다.

RESUME의 sessionResumption은 여전히 fieldMask에서 제외되어 브라우저 handle을 보존한다. systemInstruction·모델·음성·도구 금지 제약은 유지한다. Swagger/API 경로·필드 구조는 그대로다.

## R2: 외부 키 생성 전 복구 의도 확정

UserKeyStore.reference(allocationId)는 외부 키를 만들지 않고 새 할당의 안정적인 참조를 제공한다. 실제 create 결과는 이 참조와 일치해야 한다. TransientKeys는 소유자 ID와 별개의 새 UUID로 할당하여 이전 키 참조를 재사용하지 않는다. 현재 FileUserKeyStore에 구현했으며 향후 운영 저장소도 이 계약을 구현해야 한다.

1. 키를 만들기 전에 별도 트랜잭션으로 keyDiscardJob을 커밋한다. 기록 실패 시 외부 키는 만들지 않는다.
2. 본 트랜잭션에서 해당 작업을 DELETE하여 행 잠금을 유지한 후 키를 만든다. 작업이 이미 worker에게 처리되었다면 키를 만들지 않는다.
3. 본 트랜잭션 커밋 시 업무 데이터와 작업 제거가 함께 확정된다. 롤백 시 미완료 작업이 다시 보이며 즉시 폐기를 시도한다.
4. DB 오류로 즉시 폐기가 어렵거나 callback 실행 전에 서버가 종료되어도 복구 의도는 DB에 남는다. worker는 본 트랜잭션의 결과가 확정된 후에만 행 잠금을 획득해 안전하게 폐기한다. 커밋 결과 불명도 같은 DB 기록으로 판정한다.

기존 키를 폐기하는 outbox 경로와 30초 재시도 정책은 유지한다. 새 키 준비 작업도 같은 테이블을 사용한다. 작업은 소유 데이터와 무관하게 보존되며 미완료 작업을 TTL로 삭제하지 않는다. 기존 버전에서 이미 참조를 잃은 키까지 자동 복구하는 기능은 아니다.

## DB 업데이트

기존 DB에 `20260913-key-discard-job.sql`을 적용한 후 `20260914-call-prompt-anchor.sql`을 한 번 적용한다. 둘 다 `server/db/migrations`에 있다. 이미 적용한 첫 마이그레이션은 생략할 수 있다. 신규 설치는 갱신된 schema-mysql.sql을 사용한다. 스키마는 20개 테이블·195개 컬럼·174개 제약이다.

기존 통화에 임의 HMAC을 채우지 않는다. 업데이트 전에 시작한 통화는 재개 시 안전하게 종료할 수 있으므로 진행 중 통화가 끝난 뒤 앱을 교체하는 것이 적절하다. 이번 작업은 실제 서비스 DB를 변경하지 않는다.

## 검증 범위

최종 결과는 **단위 51개 + 통합 143개 = 194개 통과**, 실패·오류·생략 0이다. `bootJar` 성공, DDL 사본 바이트 일치, `git diff --check` 통과를 확인했다. [결과 JSON](verification-backend-additional.json)에 suite 시각과 스키마 SHA-256을 기록했다. 최종 회귀는 기존 HEAD DDL + 20260913 마이그레이션 + 20260914 마이그레이션으로 구성한 임시 스키마를 사용했다. 신규 DDL 경로도 앞선 전체 실행에서 통과했다.

기존 회귀와 함께 회원의 생일 경계에서 동일 지침 재개, 프로필/release 변경 거절, 기존 통화 검증 정보 누락, 큐 INSERT 실패 시 외부 키 생성 금지, 롤백 시 추가 INSERT 불필요, 폐기 실패 후 새 worker 복구, callback 없는 롤백 복구, 커밋된 키 유지, 생성 중 동시 정리의 키 보호를 검사한다.

격리 MySQL과 모의 외부 API를 사용한다. 신규 DDL 및 기존 DDL에 두 마이그레이션을 적용하는 경로를 검증한다. 실제 Gemini의 대화 문맥 유지 검수와 운영 외부 키 저장소 구현은 별도 배포 조건이며 완료했다고 간주하지 않는다.
