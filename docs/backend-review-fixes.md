## 기존 DB 업데이트

앱 업데이트 전에 대상 DB를 선택하고 `db/migrations/20260913-key-discard-job.sql`을 적용한다. 마이그레이션은 `keyDiscardJob`만 추가한다. 새 DB는 갱신된 `db/schema-mysql.sql`을 사용한다. 실제 서비스 DB에는 이번 작업에서 마이그레이션을 실행하지 않았다.

새 테이블에는 키 원문·토큰·공급자 오류를 저장하지 않는다. 성공한 작업은 즉시 제거하고, 실패한 작업을 보관 기간만으로 삭제하지 않는다. 백업 복원에도 미완료 폐기 작업을 포함해야 한다. 과거 버전에서 이미 DB 참조를 잃은 키는 이 마이그레이션만으로 찾아낼 수 없으므로 외부 키 저장소와의 별도 대조가 필요하다.

IP 판정은 현재 `server.forward-headers-strategy: none`에서 servlet remote address를 사용한다. 클라이언트의 Forwarded 헤더는 직접 해석하지 않는다. 프록시 뒤에 배포할 경우 승인된 프록시만 실제 IP를 전달하도록 컨테이너/네트워크 설정을 검수해야 한다. 그렇지 않으면 같은 프록시를 쓰는 접속자가 하나의 IP 한도를 공유한다. IP 원문은 저장하지 않으며 날짜별 HMAC 버킷은 기존 만료 정리 경로를 따른다.

## 검증 범위와 남은 배포 조건

실행 결과: 단위 **51개**, 격리 MySQL 통합 **136개**, 합계 **187개** 성공. 실패·오류·생략 0. `bootJar` 성공. 기존 171개에서 회귀 16개를 추가했다. 최초 실행의 구형 스키마 수량 검사 1건을 새 테이블 수량으로 갱신한 뒤 전체를 재실행했다. DDL 내용은 같았으나 사본의 줄바꿈 형식이 달라 두 파일을 동일 바이트로 정규화했다.

자동 테스트는 임의 포트의 격리 MySQL과 합성 사용자·모의 외부 API만 사용한다. 실제 카카오·Gemini 호출이나 서비스 DB 변경은 포함하지 않는다. Gradle XML 집계와 DDL 동기화 결과는 `verification-backend-review.json`에 기록한다.

Gemini 공식 계약: https://ai.google.dev/api/generate-content#v1beta.AuthToken — 마스크 필드는 브라우저 setup을 덮어쓴다. 세션 관리: https://ai.google.dev/gemini-api/docs/live-api/session-management — 브라우저가 최신 handle을 재연결에 전달한다.

실제 token 발급 → 초기 연결 → handle 수신 → 재개 → 이전 문맥/안전 지침 유지 시험은 검수한 모델/API 조합에서 수행해야 한다. 현재 검증은 요청 계약 검사이며 공급자 실연동 완료로 간주하지 않는다.

운영 외부 UserKeyStore는 기존과 같이 미구현이며 prod 시작 보호는 유지한다. 운영 키 저장소 공급자·권한·폐기/백업 정책을 갖춘 실제 구현과 검수가 필요하다. 로컬 파일 저장소로 대체하거나 시작 검사를 해제하지 않는다.
