# 전체 재검토 발견 사항 수정 — 2026-09-14

## 변경 내용

전체 재검토에서 재현한 두 문제를 수정했다. Swagger 경로·HTTP 메서드·요청 및 응답 필드 변경은 없다.

1. `connectionGrant.issuingStartedAt`을 추가하고 PENDING → ISSUING 전환과 동시에 기록한다. 발급 결과 저장 전 만료 검사와 워커의 만료 대상 조회 모두 이 시각부터 제한 시간을 계산한다. 대기열에서 보낸 시간은 발급 처리 제한 시간에 포함하지 않으며, 통화 수명과 lease 제한은 계속 적용한다. 기존 ISSUING 데이터에 시작 시각이 없으면 재발급 없이 UNKNOWN으로 종료한다.
2. `KeyCreationJournal`이 업무 풀과 분리된 최대 2개 연결의 Hikari 풀에서 복구 기록을 커밋한다. 업무 풀의 연결을 모두 점유한 요청들도 복구 기록을 준비할 수 있다. 전용 풀은 짧은 INSERT/커밋에만 사용하고, 외부 키 저장소 호출이나 폐기 워커의 행 잠금에는 사용하지 않아 해당 작업이 복구 기록용 연결을 점유하지 않는다. 같은 DB 설정을 복사하고 앱 종료 시 풀도 닫는다.

복구 기록의 선행 커밋, 업무 트랜잭션의 행 잠금, 롤백 및 프로세스 중단 후 복구, 기존 키 폐기 재시도 동작은 유지한다. DB 자체 장애나 전용 풀의 처리 용량을 넘는 부하까지 무제한 수용하는 변경은 아니다. 인스턴스당 DB 연결 예산에 전용 연결 최대 2개를 반영해야 한다.

## 검증

단위 51개 + 격리 MySQL 통합 148개 = **199개 모두 통과**, 실패·오류·생략 0이다. 신규 DDL과 기존 HEAD DDL에 세 마이그레이션을 적용한 경로 모두 전체 회귀를 통과했다. `bootJar` 빌드와 `git diff --check`도 성공했다. 새 회귀 테스트 5개는 최초 발급의 11초 대기 후 토큰 사용, 재개 발급의 11초 대기 후 토큰 사용, 지연된 선점 이후 9초/10초 만료 경계와 워커 조회, 구버전 ISSUING 처리, 업무 연결 4개를 모두 점유한 동시 키 생성 4건의 성공을 검증한다. 기존 키 생성 실패·롤백·폐기 재시도·동시 정리 회귀도 포함한다.

최종 마이그레이션 경로의 실행 결과는 [검증 JSON](verification-backend-full-review.json)에 기록했다. 외부 Gemini/Kakao 호출은 모의 응답이며 실제 Gemini Live 연결 및 운영 외부 키 저장소 검수는 별도다.

## 적용

기존 DB에는 앱 교체 전에 아직 적용하지 않은 아래 마이그레이션을 순서대로 한 번씩 적용한다.

1. `db/migrations/20260913-key-discard-job.sql`
2. `db/migrations/20260914-call-prompt-anchor.sql`
3. `db/migrations/20260914-grant-issuing-start.sql` — 이번에 추가

신규 설치용 DDL과 설계 DDL 사본은 동기화했다. 현재 스키마는 20개 테이블·196개 컬럼·174개 제약이다. 실제 서비스 DB에는 마이그레이션을 실행하지 않았다.
